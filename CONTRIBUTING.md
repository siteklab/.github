# Contributing

Thanks for your interest in the Speech and Hearing Pathways Lab's work. This guide applies to every repository in the
[siteklab](https://github.com/siteklab) organization unless a repository has its own `CONTRIBUTING.md`.

Everyone taking part is expected to follow our [code of conduct](CODE_OF_CONDUCT.md).

## Reporting a problem or asking a question

Open an issue in the relevant repository. Include what you expected, what happened instead, and enough detail for
someone else to reproduce it (versions, commands, error messages). Please don't attach participant data or anything
that could identify a research participant.

## Proposing a change

1. Fork the repository, or create a branch if you're a lab member.
2. Keep each pull request focused on one change, and describe what it does and why.
3. If the change affects how code is run or what it produces, update the README or documentation in the same pull
   request.
4. Open the pull request against `main`. A maintainer will review it. Expect questions, which are part of the process.

Small fixes such as typos, broken links and unclear wording are always welcome, including in the
[lab handbook](https://github.com/siteklab/handbook).

## Lab members

How we use git, organize data in BIDS, keep READMEs and handle authorship is described in the
[lab handbook](https://siteklab.github.io/handbook/), especially the Data Management & Security, Open Science and
Authorship chapters. Repositories are private while a project is in progress and become public at publication.

## Data and privacy

Never commit participant data, protected health information, credentials or passwords to any repository, public or
private. If you think something sensitive was committed, tell Kevin Sitek
([kevin.sitek@utdallas.edu](mailto:kevin.sitek@utdallas.edu)) right away rather than trying to fix it quietly.
Removing it from git history takes care.
